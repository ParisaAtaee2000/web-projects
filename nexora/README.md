# NEXORA Frontend

رابط کاربری فروشگاه NEXORA با React، TypeScript و Vite توسعه داده شده است. این پروژه شامل تجربه خرید مشتری و آماده‌سازی لایه اتصال به بک‌اند Django است. پیاده‌سازی بک‌اند، مدیریت پایگاه داده، احراز هویت واقعی و پرداخت در محدوده این مخزن فرانت‌اند نیست.

## اجرا

~~~bash
npm install
npm run dev
~~~

برای ساخت خروجی نهایی:

~~~bash
npm run build
npm run preview
~~~

برای تنظیم آدرس بک‌اند، فایل .env.example را به .env.local کپی کنید و مقدار VITE_API_BASE_URL را قرار دهید. تا زمانی که API آماده نشده است، صفحات فروشگاه از داده نمونه src/data/store.ts و وضعیت مرورگر استفاده می‌کنند.

## بخش‌های موجود

- صفحه اصلی، فروشگاه، جست‌وجو، فیلتر دسته‌بندی و مرتب‌سازی قیمت
- صفحه جزئیات محصول و کارت محصول
- سبد خرید با ذخیره‌سازی محلی و اعتبارسنجی داده‌های ذخیره‌شده
- علاقه‌مندی‌ها با قابلیت افزودن و حذف
- فرم‌های حساب کاربری نمایشی و پیش‌نمایش سفارش
- صفحات مجله، مقاله، درباره، تماس و راهنما
- حالت‌های خالی و پیام‌های بازخورد فرم
- لایه مشترک درخواست HTTP در src/services/apiClient.ts
- قراردادهای اولیه داده در src/types/api.ts
- لوگوی برداری NEXORA برای هدر، فوتر و favicon

## محدودیت‌های نسخه نمایشی

ورود و ثبت‌نام، سفارش‌ها، علاقه‌مندی‌ها و پیش‌نمایش Checkout فعلاً سمت مرورگر هستند. هیچ تراکنش واقعی انجام نمی‌شود و هیچ اطلاعاتی به سرور ارسال نمی‌شود. فرم تماس و خبرنامه نیز پس از اتصال endpointهای بک‌اند فعال خواهند شد. این موضوع در رابط کاربری با پیام حالت نمایشی مشخص شده است.

اطلاعات محصولات، قیمت‌ها و ویژگی‌ها داده نمونه هستند و پیش از عرضه عمومی باید با اطلاعات تأییدشده کسب‌وکار جایگزین شوند. لوگوی SVG نیز بازسازی برداری بر اساس تصویر مرجع ارائه‌شده است؛ در صورت تحویل فایل اصلی SVG یا PNG می‌توان آن را بدون تغییر طراحی جایگزین کرد.

## قرارداد اولیه برای هماهنگی با Django

مسیرهای زیر پیشنهاد اولیه فرانت‌اند هستند و تا زمان توافق با برنامه‌نویس بک‌اند، قرارداد قطعی API محسوب نمی‌شوند:

| Method | Endpoint پیشنهادی | کاربرد |
|---|---|---|
| GET | /api/v1/categories/ | دسته‌بندی‌ها |
| GET | /api/v1/products/ | فهرست، جست‌وجو و فیلتر محصولات |
| GET | /api/v1/products/{slug}/ | جزئیات محصول |
| POST | /api/v1/auth/register/ | ثبت‌نام |
| POST | /api/v1/auth/login/ | ورود |
| POST | /api/v1/auth/logout/ | خروج |
| GET | /api/v1/auth/me/ | اطلاعات کاربر جاری |
| GET/POST | /api/v1/cart/ | دریافت و همگام‌سازی سبد |
| GET/POST | /api/v1/favorites/ | علاقه‌مندی‌ها |
| POST | /api/v1/orders/ | ایجاد سفارش |
| GET | /api/v1/orders/ | تاریخچه سفارش‌های کاربر |
| POST | /api/v1/payments/initialize/ | شروع پرداخت |
| POST | /api/v1/contact/ | ارسال پیام تماس |
| POST | /api/v1/newsletter/subscribe/ | عضویت خبرنامه |

### قراردادهای مهم

- مبلغ‌ها در API به‌صورت عدد صحیح و با واحد مشخص (پیشنهاد: IRR) ارسال شوند.
- قیمت نهایی و اعتبار موجودی باید در بک‌اند محاسبه و تأیید شوند؛ مقدار فرانت‌اند قابل اعتماد نیست.
- ساخت سفارش و پرداخت باید در برابر درخواست تکراری مقاوم باشد.
- وضعیت‌های سفارش و خطاهای اعتبارسنجی باید در پاسخ API مستند شوند.
- روش احراز هویت، CSRF، CORS و شکل دقیق payloadها باید پیش از اتصال نهایی با تیم بک‌اند هماهنگ شود.
- تصاویر محصول باید با URL کامل یا مسیر media قابل استفاده در فرانت‌اند ارائه شوند.

## ساختار مهم

- src/components/: کامپوننت‌های رابط کاربری و Contextها
- src/pages/: صفحات فروشگاه
- src/data/store.ts: داده‌های نمونه
- src/lib/demoData.ts: داده‌های محلی صرفاً برای پیش‌نمایش
- src/services/apiClient.ts: لایه مشترک درخواست به Django
- src/types/api.ts: قراردادهای تایپ‌شده اولیه
- src/styles.css و src/styles.frontend.css: استایل‌های اصلی و تکمیلی

## مسیرها و استقرار

مسیرهای صفحه در حال حاضر با pathname مرورگر مدیریت می‌شوند و پیوندها بارگذاری کامل صفحه دارند. وب‌سرور میزبان باید برای مسیرهای فرانت‌اند مانند /shop، /cart و /product/... در صورت نبود فایل فیزیکی، index.html را برگرداند (SPA fallback).

## یادداشت تحویل

پنل مدیریت اختصاصی در محدوده فرانت‌اند این نسخه نیست؛ برای مدیریت اولیه می‌توان از Django Admin استفاده کرد. فرانت‌اند مشتری پس از نهایی‌شدن endpointها و روش احراز هویت، به API واقعی متصل خواهد شد.
