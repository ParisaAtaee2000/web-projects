# NEXORA

فرانت‌اند راست‌چین فروشگاه اشتراک‌های دیجیتال با React، TypeScript و Vite. این مخزن فقط رابط کاربری مشتری را نگه می‌دارد؛ بک‌اند Django، دیتابیس، احراز هویت عملیاتی و درگاه پرداخت واقعی در این پروژه وجود ندارند.

## اجرا

```bash
npm ci
npm run dev
```

نیازمندی: Node.js نسخه `20.19+`.

برای بررسی خروجی production:

```bash
npm run build
npm run preview
```

## ساختار

- `src/app/`: مسیریابی React Router، Layout و ترکیب Providerها
- `src/components/`: اجزای مستقل بر اساس قابلیت
- `src/pages/`: صفحات فروشگاه و محتوا
- `src/contexts/`: وضعیت مشترک سبد خرید و علاقه‌مندی‌ها
- `src/data/`: داده‌های نمونه و مدل UI
- `src/services/`: لایه ارتباط HTTP و متدهای typed API
- `src/types/` و `src/adapters/`: قرارداد داده و تبدیل پاسخ API به مدل رابط
- `src/styles/components/`: استایل‌های تفکیک‌شده بر اساس کامپوننت/قابلیت
- `docs/backend-handoff.md`: قرارداد پیشنهادی Django، محدودیت‌ها و چک‌لیست تحویل

## مسیرهای برنامه

- `/` خانه
- `/shop` فروشگاه
- `/product/:slug` جزئیات محصول
- `/cart` سبد خرید
- `/checkout` تکمیل سفارش
- `/journal` فهرست مقاله‌ها
- `/journal/:id` جزئیات مقاله (شناسه فعلی عددی است)
- `/help` راهنما
- `/about` درباره ما
- `/contact` تماس
- `/account` حساب کاربری
- `/favorites` علاقه‌مندی‌ها

در هاست production باید fallback مسیرهای SPA به `index.html` تنظیم شود تا بازکردن مستقیم و refresh مسیرهای بالا کار کند.

## اتصال به Django

فایل `.env.example` را به `.env.local` کپی کنید:

```dotenv
VITE_API_BASE_URL=
VITE_ENABLE_REMOTE_CART=false
```

- با تنظیم `VITE_API_BASE_URL`، صفحات کاتالوگ و مقاله درخواست API می‌فرستند و در صورت خطا به داده‌های نمونه برمی‌گردند.
- سفارش، حساب، تماس و خبرنامه متدهای typed دارند؛ فعال‌سازی آن‌ها به endpoint واقعی و قرارداد قطعی بک‌اند نیاز دارد.
- سبد خرید و علاقه‌مندی‌ها به‌صورت پیش‌فرض محلی هستند. همگام‌سازی سبد اختیاری است و فقط پس از پیاده‌سازی endpoint و احراز هویت با `VITE_ENABLE_REMOTE_CART=true` فعال شود.
- علاقه‌مندی‌ها در حال حاضر server-sync ندارند.
- Checkout فقط سفارش ایجاد می‌کند؛ پرداخت خودکار یا تأیید تراکنش پیاده‌سازی نشده است.
- API client کوکی‌ها را با `credentials: include` ارسال می‌کند، اما دریافت توکن CSRF و ارسال `X-CSRFToken` هنوز پیاده‌سازی نشده است. قرارداد احراز هویت و CSRF باید پیش از فعال‌سازی session auth تکمیل شود.
- داده‌ها و قیمت‌های موجود در کاتالوگ نمونه‌اند. بک‌اند باید قیمت، تخفیف و موجودی را سمت سرور محاسبه و اعتبارسنجی کند.

**فروش واقعی را تا زمان پیاده‌سازی و تست بک‌اند، احراز هویت/CSRF، اعتبارسنجی سفارش و چرخه کامل پرداخت فعال نکنید.**

جزئیات قرارداد API، نمونه payloadها، تصمیم‌های موردنیاز، ترتیب پیاده‌سازی بک‌اند و QA واکنش‌گرایی در [راهنمای تحویل بک‌اند](docs/backend-handoff.md) آمده است.

## وضعیت واکنش‌گرایی و تست

CSS در breakpointهای 1000px، 760px، 430px و 360px بازبینی شده است؛ build و TypeScript نیز در CI بررسی می‌شوند. این بازبینی کد جایگزین تست بصری دستی روی دستگاه واقعی و مرورگرهای مختلف نیست. چک‌لیست QA قبل از انتشار در مستند تحویل آمده است.
